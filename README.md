# Shield

**Screen-level Hiding of Identifiable Elements using Local Detection**

A browser extension that lets an AI agent see and use your screen **without
your private things ever reaching a server**. Built by Team Anarchy.

New here? Read [HOW_IT_WORKS.md](./docs/HOW_IT_WORKS.md) — the whole project
explained in plain words, no jargon.

---

## What it does

AI agents that use your computer take a picture of your screen and send it to a
server. That picture has everything on it — your password, your face, your
Aadhaar number.

Shield's idea: **the AI does not need to see your private things to help you.**
It needs to know there is a password box in that spot. Not what the password is.

So Shield finds the private parts **on your own computer**, paints solid black
boxes over them, replaces the real text with labels like `[PASSWORD]`, and only
then sends anything. The cloud AI replies with one action — click, type or
scroll, nothing else — and Shield carries it out.

The local part takes about **135 milliseconds**, roughly a seventh of a second.

---

## Who it's for

People whose screens are full of other people's data, and who are not allowed
to use AI agents because of it: bank KYC teams, college admissions offices, HR
and payroll, customer support. Shield lets them hand routine work to an AI
agent while every name, Aadhaar, PAN, account number and salary stays on the
laptop.

**See it in two minutes:** load the extension, run the backend, then open
[`test-screens/index.html`](./test-screens/index.html). It lists four
workplaces (bank KYC, admissions, payroll, support desk), each with a task to
type into Shield. While the AI decides, the page shows exactly what the AI
sees: black labels where the private data was. Afterwards, **What was sent?**
in the Shield panel shows the exact message that left the laptop, and
**Compliance report** shows it the way a security team would.

## Status

**Working end to end on Chrome, Edge and Firefox.** Login autofill, multi-field
sign-up, and face detection are all complete.

| What we measure | Result |
|---|---|
| Private things found (recall) | **92.4%** — about 92 out of every 100 |
| Correct when it flags (precision) | **83.5%** |
| Redaction precision | **83.9%** — of what it covers, most needed covering |
| Page left readable | **96.5%** |
| One full local pass | **~135ms** |
| Automatic tests | **465** client, **171** server |

Measured against 50 pages with the private parts labelled by hand.
[BENCHMARK.md](./docs/BENCHMARK.md) is generated by `npm run benchmark` and
never written by hand.

### The numbers that are not flattering

We publish these too, because a number you cannot check is not evidence.

**Blanket-blurring the whole screen beats us on coverage.** It scores 100% by
destroying all 891 harmless elements on the page — every button and label the
agent needs in order to act. A test makes sure it keeps winning that column, so
that if Shield ever won everything we would know the comparison had been
weakened rather than the detector improved.

**Our screen-reading score is 22.2%**, pooled over ten real pages. It replaced a
31.6% figure that came from one page and was flattering by nine points.

### The one rule, enforced three ways

> No raw private data leaves your computer, under any code path.

1. The code cannot even *build* a message that has not passed redaction
2. A runtime check confirms every step ran, in order
3. Before sending, it searches the **whole** message for anything it flagged —
   and refuses to send if it finds one

Guard 3 caught a real bug two days before the event: a name was hidden in a form
field but still present in a button's label elsewhere on the page. It refused to
transmit. Nothing leaked.

### What it does not do

Written down rather than discovered:

- **Names come from a list, not a model.** A few hundred common first names. A
  name not on the list is not found.
- **Only English is read from pictures.** A Hindi page gives nonsense guesses,
  and we do not count them as results.
- **It sees one screen at a time when acting**, and tells you how much of the
  page it looked at, every run.
- **Small faces are missed** — reliable above 110px wide, unreliable near 80px.

Full list with reasons: [SECURITY_PRIVACY.md](./docs/SECURITY_PRIVACY.md).

## Setup

**You need:** Chrome, Node.js 24+, Python 3.14. **No API key** — the backend
runs the whole demo with no model and no internet.

```bash
# extension
cd extension
npm install
npm run build
# then: chrome://extensions -> Developer mode -> Load unpacked -> extension/dist

# backend
cd server
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Windows
# .venv/bin/python -m pip install -r requirements.txt     # macOS/Linux
.venv/Scripts/python -m uvicorn main:app --port 8787
```

Check it is up: `curl http://127.0.0.1:8787/health`

**Firefox:** `npm run build:firefox`, then load
`extension/dist-firefox/manifest.json` from `about:debugging`. Firefox blocks
extensions on `file://` pages, so the local test screens need
`extensions.content_script_on_file_urls` set in `about:config`.

Full steps, including the commit guard and a table of what each failure means:
[SETUP.md](./docs/SETUP.md).

## How to use it

Load the extension, start the backend, open a page with a form. The toolbar icon
opens everything.
**Ask it to do something.** Type a task in plain words — *"log in with my saved
details"*. Shield reads the screen, covers anything private, sends only the safe
version, and performs the one action it gets back.

**Or look without acting.** *"Scan the whole page"* walks the whole document and
**sends nothing at all**. That is why it can afford to read pixels slowly in a
way a 135ms run cannot.

**Hide something yourself.** Drag a box over anything Shield missed. It stays
hidden on every run after that.

**Then check what happened** — these three screens are the point of the project,
not debug tools:

- **What was sent** — the exact message that left, saved *before* it was sent,
  so it still has an answer when the network fails
- **See what it looked at** — a blacked-out picture of every screen a scan read
- **What has been hidden** — every run, with counts and categories. Exports with
  no page content, no values and no web addresses, so you can hand it to someone

**Ask before sending** shows you each message and waits. Off by default, because
what keeps your data here is not this switch — it is the three guards above,
which ask nobody's permission.

**For an organisation:** open `http://127.0.0.1:8787/admin` on the server. Every
laptop running Shield reports its counts there — never page content, values or
web addresses — and one switch makes every employee approve each request before
it is sent. Laptop name, team and reporting are in Shield's Settings.

**Two models, checked.** Name a backup in `SHIELD_MODEL_BACKUP_NAME` and a slow
or failed first model hands over to it before the rules. A click on a table row
must quote that row's words as evidence, and the server refuses it if the quote
is from another row, is not on the page, or shows a condition that is not met.

## Packaging

```bash
cd extension && npm run package
```

Builds both browsers and writes store-ready archives plus a `SHA256SUMS` file.
The archives are checked by unpacking them again, not trusted. Packaging refuses
outright if the build carries the developer panel.

One honest caveat: these are **not reproducible builds.** Each build stamps in a
timestamp so a running extension can say which build it is, so two clean builds
of the same commit have different checksums.

**The server in a container:**

```bash
docker build -t shield-server ./server
docker run --rm -p 127.0.0.1:8787:8787 shield-server
```

202MB, runs as a non-root user. **Keep the `127.0.0.1:` prefix.** This server has
no login and no rate limit by design, because it is meant to be reached from the
same machine. Without that prefix, anyone who finds it can drive it.

Shield asks for `activeTab`, `scripting`, `storage`, `offscreen` and `sidePanel`.
It has no access to sites you have not opened it on. On Chrome it opens in the
side panel **on the tab whose icon you clicked, and only that tab** — switch tabs
and it goes away, because Shield has no permission there. Firefox uses a popup.
