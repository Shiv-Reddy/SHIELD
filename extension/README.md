# Shield — Chrome Extension Client

The client half of Shield. Captures the screen, detects and redacts sensitive
regions locally, and sends only sanitized context to the backend. See the
project docs for the full picture: [ARCHITECTURE.md](../docs/ARCHITECTURE.md),
[SECURITY_PRIVACY.md](../docs/SECURITY_PRIVACY.md),
[API_SPEC.md](../docs/API_SPEC.md).

## Build and load

```bash
cd extension
npm install
npm run build
```

Then in Chrome:

1. Open `chrome://extensions`
2. Turn on **Developer mode** (top right)
3. **Load unpacked** → select `extension/dist`

`npm run watch` rebuilds on change. Chrome does not hot-reload extensions;
after a rebuild, hit the reload icon on the Shield card in `chrome://extensions`,
then reload the page you're testing on so the content script is re-injected.

## Scripts

| Script | What it does |
|---|---|
| `npm run build` | Full production build into `dist/` |
| `npm run watch` | Rebuild on file change |
| `npm run typecheck` | `tsc --noEmit`, no build output |
| `npm run icons` | Regenerate the icon set (build does this for you) |
| `npm run verify-models` | Check pinned models against their hashes (build does this too) |
| `npm run clean` | Delete `dist/` |

## Layout

```
extension/
  public/
    manifest.json         MV3 manifest; copied to dist/ verbatim
    icons/                generated by tools/make-icons.mjs, not committed
    models/               pinned local ONNX models, committed and hash-checked
  src/
    background/
      service-worker.ts   orchestrator; owns pipeline order
      capture.ts          viewport capture and frame decoding
    content/
      content-script.ts   only code that runs in the page; injected on demand
    popup/
      popup.html/.ts/.css status surface and task entry
    lib/
      types.ts            the pipeline's type contract, including the redaction seal
      status.ts           status vocabulary and pipeline stage order
      messages.ts         typed message envelopes between the three contexts
      timing.ts           per-stage timing against the ARCHITECTURE.md budget
  tools/
    make-icons.mjs        generates the PNG icon set from source
    models.json           pinned model manifest: source, licence, sha256, graph I/O
    verify-models.mjs     checks model hashes; the build fails if one drifts
```

## Watching a run

Right-click the Shield icon → **Inspect popup** for the popup console. For the
pipeline itself, open `chrome://extensions`, find Shield, and click the
**service worker** link — that console is where capture dimensions, per-stage
timings, and over-budget warnings are logged.

A healthy capture looks like:

```
[shield] screen capture 61.4ms / 100ms
[shield] captured 3024x1890 device px (dpr 2, scale 2.000x2.000)
```

Runs currently stop after capture with an explicit "not implemented yet"
message, which is expected until the next module lands.

## Two things worth knowing before you change anything

**The redaction seal.** `lib/types.ts` defines `Sanitized<T>` using a
non-exported `unique symbol`. Nothing outside the Redaction Engine can produce
a value of that type, and the Transport Layer accepts nothing else. If you find
yourself wanting to cast your way past it, that is the type system correctly
telling you that you are about to transmit something that was never redacted.

**Two guards, on purpose.** The seal is a compile-time check. The service
worker separately tracks which pipeline stages actually completed and refuses
to advance past `sending` if `redacting` never ran. The first catches bad
wiring, the second catches a stage that threw or returned early. Neither is
redundant.

## Permissions, and why each one

| Permission | Why |
|---|---|
| `activeTab` | Capture the visible tab and inject the content script — only on the tab the user explicitly ran Shield on, only after they clicked. |
| `scripting` | Inject the content script on demand. |
| `storage` | Local preferences. Nothing captured from a page is ever stored. |

There is no `content_scripts` block in the manifest and no host permissions.
Shield has no presence at all on pages the user hasn't pointed it at.

## Build notes

The build runs Vite twice. The popup and service worker can ship as ES modules
and share chunks; content scripts run in a classic script context and cannot,
so `vite.content.config.ts` bundles that one entry into a self-contained IIFE.

Output is deliberately unminified. Anyone should be able to read the shipped
code and confirm the privacy claim for themselves.
